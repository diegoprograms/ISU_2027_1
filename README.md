# Anteproyecto — ISU 2027

Espacio de trabajo para redactar y revisar el anteproyecto con los docentes participantes.

## Documentos

- [Anteproyecto](anteproyecto.md): versión maestra de la propuesta.
- [Acuerdos y pendientes](acuerdos.md): decisiones y preguntas por resolver.
- [Requisitos](convocatoria/requisitos.md): requisitos y criterios de evaluación de la convocatoria.
- [Equipo](equipo/responsabilidades.md): perfiles, dedicación y responsabilidades.
- [Plan de trabajo](planificacion/plan-de-trabajo.md): cronograma, productos y continuidad entre semestres.
- `referencias/`: propuesta inicial, antecedentes y fuentes de apoyo.
- [Anteproyecto inicial en PDF](referencias/anteproyecto-inicial.pdf): original de prefactibilidad aportado por el equipo, pendiente de revisión.
- `entregables/`: versiones para presentar en Word o PDF.
- [Instrucciones para Codex](AGENTS.md): pautas comunes para las sesiones de los docentes.

## Forma de trabajo

1. Incorporar los términos de la convocatoria y extraer sus requisitos.
2. Revisar la propuesta inicial y ajustar la estructura del anteproyecto al formato exigido.
3. Incorporar los perfiles docentes y acordar responsabilidades y productos.
4. Actualizar la versión maestra y registrar las decisiones relevantes.
5. Guardar avances coherentes en Git con mensajes que expliquen los cambios.

Los aportes y revisiones se integrarán en una única versión maestra. Los datos aún no confirmados se marcarán como pendientes; no se inventarán requisitos, antecedentes ni compromisos docentes.

Git conserva el historial local de los archivos. Para colaborar desde distintos equipos, se podrá conectar este repositorio a GitHub y acordar un flujo de revisión. Los acuerdos necesarios para continuar el trabajo deben quedar en los documentos, además de las conversaciones.

Si el anteproyecto es aprobado, este repositorio servirá como base para su ejecución.

## Colaboración entre docentes

Cada docente podrá conversar con Codex sobre su copia del repositorio y actualizar los archivos. GitHub permitirá compartir los cambios cuando se configure el repositorio remoto y los accesos del equipo.

Las conversaciones no se sincronizan mediante Git. Registrar los acuerdos en los documentos permitirá que las otras sesiones retomen el trabajo. Para aportes simultáneos, se propone trabajar en ramas separadas e integrar mediante solicitudes de cambios.
